# P1-F：会話に渡す根拠の可視化と、Reflectionの扱い

会話品質の根本原因の調査（2026-11-12、main 8615008）で見つかった問題への小さな改善。

## 変えたこと

### 1. 診断（`?debugLog=1` のときだけ）
- AIの返答の `[D]` を開くと、会話AIに渡した情報が経路ごとに表示される。対象の経路は Retrieval・Reflection・Explicit Search・Topic Continuity・Topic Timeline・Memory Timeline・Memory Synthesis・Memory Graph。
- 各項目について、次を表示する。
  - Memory ID
  - 出典（metadata.source）
  - 本人の発言／後からの本人の説明・訂正／AIの要約／AIの推測の区別
  - その経路が採用した理由
  - 本文の短い抜粋（40字まで）
- 次の情報もまとめて表示する。
  - 複数の経路から渡ったMemory
  - そのターンに含まれる本人の理由・訂正（Graph の「後から本人が説明した理由」、Synthesis の「ユーザー自身の訂正」、理由・訂正の形をした本人の発言）
  - Retrieval が Reflection をどう扱ったか
  - 送ったが会話AIに渡らなかったもの（サーバーの確認・上限、時間で変わる外部の事実の除外による）
- 「送った値」は画面側で、「会話AIに渡った値」はサーバーがプロンプトに使った値から作り、両者を突き合わせて表示する。
- 保存しない。これまでの Debugger は localStorage に保存しているが、経路ごとの由来はそこに入れない。タブのメモリにだけ置くので、再読み込みすると消える。
- 新しい外部への送信はない。由来はサーバーからの応答の末尾に付くだけで、`debugGenerationId` があるときに限る。
- 診断がONでもOFFでも、プロンプト・返答・Retrievalの結果は同じ（テストで確認）。

### 2. Reflection（AIが書いた日記の振り返り）
- Reflection は本文も要約もAIの文章で、キーワードは元の記録と同じ。そのため、抽象的な質問では本人の記録より上位になりやすかった。
- 会話の Retrieval だけ、Reflection を本人の記録の後に回す（`deferReflections`）。
  - 順位は、Reflection のスコアを「自分のスコアの半分」と「1キーワード一致分」の低い方として並べ直して決める。キーワードが一致する本人の記録は前に来るが、文字の偶然の重なりだけの弱い記録が、関係の深い Reflection を押し出すことはない。
  - 同じ会話の本人の記録が選ばれていれば、その Reflection は入れない（Connect のつながり経由でも同じ）。
  - 発言が振り返りや日記に「書いたこと」を尋ねているとき（「日記に何て書いた？」など）は、従来どおりの順で選ぶ。「今日の日記：…」「今年の振り返り」のように語が出てくるだけでは、従来どおりにはしない。
- analyst の人物を考慮した選定でも同じように後ろへ回す。ただし、外した分を本人の記録で埋め直すことはしない。
- プロンプトでは `source: system-generated` の代わりに「出典: Tsumugiが書いた日記の振り返り（AIの文章。本人の発言ではない）」と示す。
- Connect・Capture、そのほかの呼び出し元は従来どおり（オプションを渡さない）。Explicit Search・Analytics・Synthesis・Topic・Graph は変えていない。

完全な除外ではなく「後に回す」にした理由：
- 発言が日記や振り返りを尋ねているときには、Reflection を見つけられる必要がある。
- 本人の記録が無い日（元の記録を消した場合など）には、Reflection しか手がかりが無いことがある。
- Reflection は同じ会話の本人の記録と内容が重なるので、本人の記録があるときは外しても失われる情報が無い。

### 3. 会話プロンプト
- 過去の情報が渡されたターンだけに「本人の過去の理由・考え・変化・訂正を聞かれたとき」の節を加える。材料を使う順は次のとおり。
  1. 本人が明示した発言
  2. 後から本人が説明した理由・訂正
  3. AIの要約
  4. AIの仮説・解釈
- 見方を求められたときは、1と2を踏まえて見解や仮説を具体的に述べてよい。そのときも本人の発言とは分けて伝え、一般論だけで返さない。
- 1と2に当たる材料が無いときは、見つかったように装わない。
- 過去の情報が無いターンは従来どおり（この節は入らず、「このターンの過去の情報」の節が入る）。

## 変えていないこと
- Capture・Vault・Memoryの保存形式。既存のMemoryも書き換えない。
- AIの呼び出し回数。
- Retrievalの点数の付け方（`scoreMemory`）。
- Timeline・Synthesis・Graph・Topic の選定。

## テスト（架空データ、`npm run test:chat-context-p1f`）
- 本人の明示的な結論と、別の動機を読み込んだ同じ日の Reflection：Reflection は本人の記録より先に来ず、同じ会話の分は入らない。
- 抽象的な振り返りの質問（A）と、具体的な理由を確かめる質問（B）：どちらでも本人の結論と後からの説明が入る。
- Reflection 自体を尋ねたとき：従来と同じ結果。
- analyst の選定、Connect のつながり経由、診断の有無による結果の違いが無いこと。
- 意見を求めたとき：見解・仮説を述べる指示が残っている。
- Timeline・Synthesis・Graph を同時にONにしたとき：全節がプロンプトに入り、診断に全経路・重複・後からの説明・訂正が出る。
- Graph などがOFFのとき：それらの節は入らない。
- Connect・Capture はオプションを渡さない（ソースで確認）。前の順も変わらない。
- 診断のON・OFFで、プロンプトと返答が同じ。

## 対象外として残したこと（未対応・未検証）
- Retrieval の点数は要約と本文から付けており、本人の逐語は使っていない。抽象的な質問では、AIの言い回しで書かれた要約が有利なまま。
- プロンプト「その他の大切な姿勢」の、過去の情報の出どころの一覧に Graph・Timeline が入っていない（以前からの食い違い）。
- Explicit Search の結果に Reflection が入ったときは、従来どおり「要約」として渡る（逐語の抜粋は無い）。
- 実機での効果：未検証。
