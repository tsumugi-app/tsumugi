# Tsumugi Roadmap

Version 1.0

---

# この文書について

これはTsumugiの開発ロードマップである。

`README.md` `VISION.md` `PROJECT.md` `REQUIREMENTS.md` `ARCHITECTURE.md` `AI_DESIGN.md` `UI_UX.md` `MEMORY_ENGINE.md` `MVP.md` が定義した思想と設計を前提とし、

それらを**どの順番で、どんな体験として積み上げていくか**を定義する。

機能のチェックリストではない。

体験の設計図である。

---

# 基本方針

ロードマップは「開発計画」であると同時に、

**「今やらないことを決める文書」**でもある。

Tsumugiには、あとから追加できる機能はたくさんある。

しかし、

**順番を間違えると壊れる体験**がある。

記憶がまだ育っていないのにつながりを見せようとしても、何もつながらない。

記憶がまだ資産になっていないのにAIを切り替えられるようにしても、失うものがない。

だからこのロードマップは、各Phaseについて次の4つを明記する。

- 目的（どんな体験を実現するか）
- 実装候補（その体験を支えるために何を作るか）
- 成功条件（体験が実現できたと言える状態）
- やらないこと（このPhaseではまだ手を出さないもの）

# Phase 1 — MVP

## 目的

**話すだけで、記憶が育ち始める体験をつくる。**

ユーザーは何かを「入力」しているとは感じない。

ただ話しているだけなのに、

気づけば自分の記憶がそこに残っている。

その体験の入口をつくるのがPhase 1である。

## 実装候補

- AIチャット — 何かを入力している感覚ではなく、ただ話している感覚をつくる
- Memory Object生成（`MEMORY_ENGINE.md` 2.2 Capture）— 話した内容が、意識せずとも記憶として残る
- Markdown保存（`ARCHITECTURE.md` Storage Layer）— 記憶が、後からでも人の目で読める形で残る
- Local First / IndexedDB — 記憶が、常に自分の手元にある
- Reflection（基本形）— 過去の会話に、もう一度光を当てられる
- 基本検索 — 探したいときに、迷わず思い出せる
- 設定画面

## 成功条件

1か月使い続けたユーザーが、

**「過去の自分と対話している」**

と感じられること。

機能が揃っていることではなく、この実感が生まれることが完了条件である。

## やらないこと

- 通知
- ゲーミフィケーション
- AI Provider切替
- プラグイン
- 複数人・チーム機能

まだ「記憶が育つ」という体験の土台すらできていない段階で、
これらを足しても体験は深まらない。むしろ体験の焦点をぼやけさせる。

---

# Phase 2 — Memory Growth

## 目的

**過去の自分が、今の自分を助ける体験をつくる。**

Phase 1で記憶は生まれた。

Phase 2では、その記憶同士が自然につながり、

ユーザーが尋ねてもいないのに、

「そういえば、前にもこんなことを話していましたね」

とTsumugiの側から差し出せるようにする。

その内側で起きているのは、単なる検索ではない。

Reflectionが過去を想起し、

**Memory Editing**がその意味を編み直し、

結果としてInspirationが立ち上がる。

**想起 → 編集 → 提案**。

Tsumugiの価値が「検索」ではなく「編集」にあることを、

体験として初めて形にするのがPhase 2である。

## 実装候補

- Memory Link（`MEMORY_ENGINE.md` 4章 Linking）— 記憶と記憶が、そっとつながる
- Memory Editing（`MEMORY_ENGINE.md` 6章 Editing）— つながった記憶から、まだ言葉になっていない意味を編み直す
- Inspiration（`MEMORY_ENGINE.md` 7章）— 編集された意味が、新しい問いや方向性として差し出される
- Seed / 発芽（`MEMORY_ENGINE.md` 8章）— まだつながっていなかった記憶が、いつか芽吹く
- Remember Moments（`UI_UX.md`）— 節目に、過去がそっと顔を出す
- Timeline / 記憶の可視化 — 育ってきた記憶の輪郭を、眺められるようにする

## 成功条件

ユーザーが意識的に「検索」しなくても、

**「昔の自分が、今の自分を助けてくれた」**

という瞬間が、自然に、繰り返し起こること。

## やらないこと

- AI Provider切替
- Markdown Import / Export、Obsidian Import
- 外部API公開
- プラグインアーキテクチャ

記憶がまだ「つながる」段階であり、「持ち出せる資産」にはなっていない。
資産化の前に、まずつながる体験を確かなものにする。

# Phase 3 — Personal Memory OS

## 目的

**AIが変わっても、人生の資産が残り続ける体験をつくる。**

`VISION.md` の「AI is replaceable. Your memories are not.」を、

思想から実際の体験へ変える段階である。

その中心にあるのは、AIの切り替えそのものではない。

**Markdown First**という原則である。

記憶が人の目にも読めるMarkdownとして存在する限り、

ユーザーはどんなツールへ移っても、人生を持ち出せる。

Obsidian対応は、その一つの現れにすぎない。

## 実装候補

- Markdown Import — 他所にあった記憶も、Tsumugiの中に迎え入れられる
- Markdown Export — Tsumugiの記憶を、いつでも自分の手元に取り戻せる
- Obsidian Import — Markdown Firstの実例として、既存の知的資産をつなぐ
- AI Provider切替 — AIが変わっても、記憶の続きが途切れない
- API — 記憶を、他のツールや仕組みからも呼び出せるようにする
- Plugin Architecture — Tsumugiの外側にも、記憶を活かす方法を広げる

- スマホUI最適化
- PWA
- iOS / Androidでの利用
- PC ↔ スマホでのMemory共有
- Vault / ローカルデータの扱い
- オフライン利用

あたりを入れておくといいです。

ただし、**今は設計思想として忘れない程度で十分**。

## 成功条件

ユーザーがAIプロバイダーを切り替えても、

**「人生の記憶は何も失われていない」**

と実感できること。

記憶がTsumugiというアプリの中身ではなく、

Markdownとして存在する、ユーザー自身の資産だと実感できること。

## やらないこと

- Community Plugin公開
- SDK公開
- チーム／複数人での記憶共有
- Research Mode

資産として記憶を持ち出せることが先であり、
それを他者と共有・拡張する仕組みはまだ早い。

# Phase 4 — Ecosystem

## 目的

**個人のための記憶から、人と人がつながる知のエコシステムへ。**

Phase 3までで、記憶は個人の資産として確立している。

Phase 4は、その資産を土台に、

Tsumugiというプロダクトそのものを

**個人向けアプリからプラットフォームへ**育てる段階である。

この段階はまだ構想レベルでよい。

## 候補（構想レベル）

- Community Plugin — 他者の作った拡張が、自分の記憶の育て方をさらに広げてくれる
- SDK — 開発者が、Tsumugiの外からも記憶とつながる仕組みを作れるようにする
- Research Mode — 個人の記憶を超えて、知を探求すること自体を支える
- Team Memory — 個人の記憶が、信頼できる誰かとの記憶にもなる
- 将来的な拡張

## 成功条件

Phase 4では厳密な成功条件を定めない。

ただし前提として、

**Phase 1〜3で確立した「個人の記憶は個人のもの」という原則を、
拡張によって壊さないこと**が唯一の制約になる。

## やらないこと

- 個人の記憶をエコシステムのために勝手に集約・学習利用すること
- 「つながり」を理由にプライバシーの原則を緩めること

Phase 4はあくまでPhase 1〜3の上に乗る拡張であり、
土台の思想を上書きしてはならない。

# Roadmap Philosophy

このロードマップが目指しているのは、

**機能を増やすことではない。**

**ユーザーの人生との対話を、少しずつ深くしていくことである。**

Phase 1では、話すだけで記憶が生まれる。

Phase 2では、その記憶が自分自身を助け始める。

Phase 3では、記憶がAIから独立した、一生ものの資産になる。

Phase 4では、その資産の上に、新しいつながりが生まれ始める。

`MEMORY_ENGINE.md` が描いた種の循環——

未発芽から発芽へ、発芽から成長へ、成長から実へ、そして新しい種へ——

と、このロードマップのPhaseは同じ構造を持つ入れ子関係にある。

Phaseが進むごとに、

**AIが賢くなっていくのではない。**

**ユーザー自身の記憶が、育っていくのである。**

Tsumugiというプロダクトの成長は、

その育ちを支える器が少しずつ大きくなっていくことでしかない。

そして、いつか。

ユーザーは気づく。

Tsumugiが育ったのではない。

育っていたのは、

自分自身だったのだと。

---

Phaseを前に進めるかどうか迷ったら、この問いに戻る。

> それは、ユーザーの記憶が育つ体験を深めるか。

> それとも、単に機能を増やすだけか。

前者でなければ、次のPhaseへは進まない。
