# Memory Graph P0：人物シート（試作・デバッグ専用）

保存済みのMemoryから、人物ごとの情報をその場で組み立てて見るための開発用ページです。
実機の記憶で、出来事・過去の考え・最後に確認できた記録・予定がどうつながっているかを確かめるために使います。

## 開き方

1. `?debugLog=1` を付けてアプリを開く。
2. Conversation Debugパネル（左上の 🗨）を開き、「人物シート（試作）」を押す（新しいタブで `/diagnostics/person-sheet` が開く）。
3. 「この端末の記憶を読み込む」を押し、人物を選ぶ。

## 守っていること

- 保存形式・既存Memory・Vaultは変更しない。読み込みは、この端末のIndexedDBを読み取り専用で開くだけ（`src/lib/personSheetRead.ts`）。
- AIは呼ばない。シートは保存しない。開くたびに組み立て直す（`src/lib/personSheet.ts`）。
- 会話の返答・Retrievalには使われない（チャット画面・`/api/chat`・`retrieval.ts`は変更なし。どこからもimportされないことをテストで確認）。
- アプリ本体（ChatScreen）をmountしないので、起動時の処理・Capture・Connectは走らない。

## シートの構成

| 節 | 内容 | 主な材料 |
|---|---|---|
| 関係の概要 | 記録数（人物として記録／名前がキーワードにあるだけ）、期間、関係の分類と根拠の発言、同じ記録に出てくる人 | PersonView（personMentions） |
| 出来事 | この人の全記録を、話した日の順に。要約・本人の発言・出来事の日付・記録の言葉（予定／中止など）・他の人・話題 | Memory、evidenceQuotes |
| 過去の考え・結論 | 考え・気持ち・判断の言葉を含む文。本人の発言が無い記録だけAIの要約から | memoryContext.tsの判定語 |
| 最後に確認できた記録 | 最後に話した記録、状態の言葉がある最後の記録、最後に述べた関係、本人の言葉での最後の考え（どれも日付付き。今の状態とはしない） | — |
| 予定とその後 | 予定・検討中、または出来事の日付が話した日より後の記録。同じ話題番号の後の記録だけを「その後」、キーワードが同じだけの記録は「候補」 | Memory Timelineの状態判定、topicId |
| 話題の発言 | この人の記録が属する話題の本人の発言すべて。同じ話題でも別の人の記録は別に示す | Topic Timeline（topicEvents） |
| Connectの推測 | この人の記録のリンク（軸・強さ・理由）。相手側がこの人の記録でないときは明示 | Connect（links） |
| テーマ | この人の記録のキーワードがMemory Timelineのテーマになっているもの（他の人の記録も含む） | Memory Timeline |

各行には「本人の発言／AIの要約／Connectの推測」の区別と、根拠のMemory（idの末尾6桁）が付きます。idを押すと、そのMemoryの保存内容（要約・本文・キーワード・本人の発言・人物・話題・日付・つながり）を表示します。
件数・文字数の上限はありません（長い節は折りたたみ）。

## 人物の取り違えを防ぐ規則

- 敬称の違いだけ（「みなとさん」と「みなと」）は同じ人。別の呼び方（名前と「妻」など）はまとめない。
- 名前がキーワードにあるだけの記録（Captureが人物として記録していない）は「名前がキーワードにあるだけ」と表示する。
- この人の名前を含む別の名前（「みなと」と「みなとこ」）は「似た名前」として示し、別人として扱う。
- 本人の発言・考えの文が別の人の名前だけを含む場合は「別の人の話かもしれない」と表示する。

## 限界（未検証を含む）

- 「記録の言葉」（予定・中止など）は要約に出てくる語の判定で、この人についての状態とは限らない。
- 考えの判定は言葉のリストによる。言葉の無い考えは拾えず、考えの言葉を含む事実の文も拾いうる。
- 人物の機能が入る前の古いMemoryには人物の記録が無く、名前がキーワードにある場合だけ見つかる。
- 実機の記憶での見え方は未検証。
