# Memory Graph P0：人物シート（試作・デバッグ専用）

保存済みのMemoryから、人物ごとの情報をその場で組み立てて見るための開発用ページです。
実機の記憶で、出来事・過去の考え・最後に確認できた記録・予定がどうつながっているかを確かめるために使います。

## 開き方

1. `?debugLog=1` を付けてアプリを開く。
2. Conversation Debugパネル（左上の 🗨）を開き、「人物シート（試作）」を押す（新しいタブで `/diagnostics/person-sheet` が開く）。
3. 「この端末の記憶を読み込む」を押し、人物を選ぶ。
4. 表示されない記憶があるときは「記憶を探す」に言葉を入れ、出ない理由を確かめる。別の名前が同じ人と思われるときは「この画面だけ一緒に見る」で一緒に表示する。

## 守っていること

- 保存形式・既存Memory・Vaultは変更しない。読み込みは、この端末のIndexedDBを読み取り専用で開くだけ（`src/lib/personSheetRead.ts`）。
- 形が想定外の記憶や項目（文字でない発言など）は表示から除き、件数を読み込み結果に示す（保存データは直さない）。
- AIは呼ばない。シートは保存しない。開くたびに組み立て直す（`src/lib/personSheet.ts`）。
- 会話の返答・Retrievalには使われない（チャット画面・`/api/chat`・`retrieval.ts`は変更なし。どこからもimportされないことをテストで確認）。
- アプリ本体（ChatScreen）をmountしないので、起動時の処理・Capture・Connectは走らない。

## シートの構成

| 節 | 内容 | 主な材料 |
|---|---|---|
| 同じ人かもしれない別の名前 | 同じ話題・Connectのつながり・共通して出てくる人がある別の名前（例：さきさん／咲さん）。推測で、まとめない。「この画面だけ一緒に見る」で一時的に一緒に表示できる（保存しない） | topicId、links、personMentions |
| 記憶を探す | すべての記憶から言葉を探し、このシートに出ているか、出ていないなら理由、文の形と扱い（考えに出した／質問として分けた／同じ文を先に出した／出来事の報告なので考えに入れない など）を示す | — |
| 関係の概要 | 記録数（人物として記録／名前がキーワードにあるだけ／本文での言及だけ）、期間、関係の分類と根拠の発言、同じ記録に出てくる人 | PersonView（personMentions） |
| 出来事 | この人の全記録を、話した日の順に | Memory、evidenceQuotes |
| 過去の考え・結論 | 本人の発言を文ごとに分け、文の形で「判断・結論（言い切り・決めたこと）」「考え・気持ち（推量・感情・望み）」としたもの。古い順、同じ文は1回（ほかの記録にもあればidを示す）。本人の発言に考えの文が無い記録だけAIの要約から | `src/lib/personStatement.ts` |
| 質問・依頼 | AIに尋ねた・確かめた・頼んだ文。考えとは分ける（折りたたみ） | 同上 |
| 最後に確認できた記録 | 最後に話した記録、状態の言葉がある最後の記録、最後に述べた関係、本人の言葉での最後の判断・結論、最後の考え（どれも日付付き。今の状態とはしない） | — |
| 予定とその後 | 話題ごとに、予定と「結果の候補」。候補は、後の記録のうち中止・保留・実施済みの言葉があり、予定と共通の言葉（名前以外）があるものだけ。同じ話題というだけの記録は結果とせず、件数だけ示す | Memory Timelineの状態判定、topicId、keywords |
| 話題の発言 | この人の記録が属する話題の本人の発言すべて | Topic Timeline（topicEvents） |
| Connectの推測 | この人の記録のリンク | Connect（links） |
| テーマ | この人の記録のキーワードがMemory Timelineのテーマになっているもの | Memory Timeline |

各行には「本人の発言／AIの要約／Connectの推測」の区別と、根拠のMemory（idの末尾6桁）が付きます。idを押すと、そのMemoryの保存内容を表示します。
件数・文字数の上限はありません（長い節は折りたたみ）。

## 文の形による分け方（`personStatement.ts`）

話題の言葉ではなく、文がしていること（尋ねる・頼む・言い切る・推し量る・起きたことを伝える）で分けます。AIは使いません。

| 分類 | 形の例 | 考えに入れるか |
|---|---|---|
| 判断・結論 | 〜ない／〜だ／〜べき／〜しかない（今のこととして言い切る）、決めた／やめる／〜ことにした | 入れる |
| 考え・気持ち | 〜と思う／〜かも／〜気がする／〜だろう？（自問）、〜たい／〜てほしい、気持ちの言葉、〜かった（感想） | 入れる |
| 質問・確認 | ？で終わる（自問を除く）、〜ですか／〜ますか、どう思う／覚えてる | 分ける |
| 依頼 | 教えて／調べて／まとめて…（ください）、お願い | 分ける |
| 出来事の報告 | 過去形で起きたことを伝える | 入れない（出来事の欄） |
| 状態の説明 | 〜している／いる／ある | 入れない（出来事の欄） |

判断・結論が今も同じかは示しません。後の判断があれば、それも日付付きで並びます。

## 人物の取り違えを防ぐ規則

- 敬称の違いだけ（「みなとさん」と「みなと」）は同じ人。別の書き方（「さきさん」と「咲さん」）や呼び方（名前と「妻」）はまとめない。
- 同じ人かもしれない別の名前は、根拠（同じ話題・Connectのつながり・共通して出てくる人）と一緒に候補として示すだけ。同じ記録に両方の名前があれば「別人の可能性」と示す。
- 「この画面だけ一緒に見る」は表示だけで、保存しない。確定は本人が行う（P1で、Vaultに保存し取り消せる形にする予定）。
- 名前がキーワードにあるだけの記録、名前が本文にあるだけの記録（2文字以上の名前）は、それぞれそう表示する。
- この人の名前を含む別の名前（「みなと」と「みなとこ」）は「似た名前」として示し、別人として扱う。
- 本人の発言・考えの文が別の人の名前だけを含む場合は「別の人の話かもしれない」と表示する。

## 限界（未検証を含む）

- 文の形の判定は規則による。句読点の無い話し言葉では2つの文がつながることがあり、？の無い質問で疑問の形で終わらないものは質問と分からない。
- 「記録の言葉」（予定・中止など）は要約に出てくる語の判定で、この人についての状態とは限らない。結果の候補も推測で、確定ではない。
- AIの要約はAIの語りなので、考えの言葉がある文だけを、本人の発言に考えが無い記録に限って使う。AIの本文（content）は考えの材料にしない（「記憶を探す」では見つかる）。
- 人物の機能が入る前の古いMemoryには人物の記録が無く、名前がキーワードか本文にある場合だけ見つかる。
- 実機の記憶での見え方は未検証。
