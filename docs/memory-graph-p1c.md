# Memory Graph P1-C：人物の背景情報の選定精度

P1-A の「会話に渡す人物の背景」で、件数の上限の中に何を入れるかを改善する。試験フラグ `?memoryGraph=1` のときだけ使う。OFF のときは従来と同じ。

- Memory・Vault の保存形式・Capture は変えない。AI 呼び出しは無い（端末内のみ、AI の種類に依存しない）。
- 上限（結論6・予定2・候補2 など）は変えない。
- 人物名や特定の表現に依存した規則にはしない。文の形と述語の種類だけで判断する。

## 実機で見えた問題（原因）

- 短い状況説明や一時的な気持ちが「結論」として優先されていた。
  - 原因：P0 の文の分類（`personStatement.ts`）は「言い切り」か「推量・思い」かだけを見ている。「もう半年だよ」「よくわからない」「消えてくれない」はどれも言い切りの形で、判断・結論になる。
  - さらに、上限を超えたときの順位が「言い切り → 思い」の順で、同じ順位の中では新しいもの優先だった。そのため「大切にしたい」「特別な存在でありたい」（願い＝思いの形）が、新しい短い言い切りに押し出された。
- 後からの説明は、結論が上限で落ちると一緒に消えることがあった。
- 要約に予定の言葉（「考えている」「つもり」）があると、AI への質問・依頼や振り返りも「予定」として渡されていた。
- 名前の無い記録は、同じ会話と同じ話題が重なるだけで（内容が無関係でも）候補になっていた。

## 改善

### 1. 考え・結論の選定（`personStance.ts`）

本人の考えの文を、何をしている文かで分ける：

| 種類 | 例（形） | 重み |
| --- | --- | --- |
| 結論 | 決めた・やめる・〜ことにした、「Xはない」（未来はない）、べき・しかない・無理・大事・必要 | 5 |
| 願い | 〜たい・〜ありたい・〜てほしい（〜と思う付きも） | 5 |
| 考え | 〜と思う・〜気がする、考えの言葉。後からの説明・訂正も考えとして扱う | 3 |
| その時の気持ち | 気持ちの言葉、〜てくれない・消えない、過去の出来事の感想（楽しかった） | 1 |
| 迷い | わからない・迷っている・どうしたらいいのか | 1 |
| 状況の説明 | 名詞＋だ／です、考えや評価の言葉が無い（もう半年だ） | 渡さない |

選び方（上限は維持）：
- 加点：後からの本人の説明があるもの +2、別の日にも同じことに触れているもの（継続している考え）+1、理由や訂正を含むもの +1。
- 減点：とても短い文（10字未満）−1、名前の無い記録（候補）−1。
- 重み1未満（短い一時的な気持ち・迷い）は渡さない。
- 1件ずつ選ぶ。すでに選んだものと同じ月・同じ言葉のものは少し下げる（時期と内容の多様性）。新しいだけでは優先しない。同じ重みなら新しいものを先にする（従来どおり）。
- 会話への表示は種類の名前（結論／願い／考え／その時の気持ち／迷い）にする。「その時の気持ち・迷いは結論ではない」「願いは予定や事実ではない」とAIに伝える。
- 本人の発言だけを使う（AI の要約は「考え」に入れない。従来どおり）。

### 2. 理由と訂正の関連づけ

- 後からの説明：理由の形（だから・〜からだ・理由は など）か、訂正・説明の形（本当は・というより・〜と言ったのは など）の本人の文。
- 結論・願い・考えにだけ結びつける（一時的な気持ちや迷いには結びつけない）。
- 結びつけるのは、この人について何かを言う共通の言葉があるときだけ。ほかの2人以上の人物の記録で本人が使っている言葉（「仕事」「関係」など）は、この人の根拠にしない（1人だけなら除かない。未確定の別名は、別の人物に見えるため）。
- Capture が両方を同じ話題（topicId）にしていれば「同じ話題」。言葉だけなら「関連は推測：共通の言葉から」と明示する。
- 古い結論は消さない。理由の形の無い新しい考えは、古い結論に結びつけず単独で扱う。
- 説明のある結論は重みが上がるので、上限で結論と理由の両方が落ちにくい。説明が別の結論の下に出たときだけ、単独では出さない。

### 3. 予定の誤分類

人物シートの予定（要約の予定の言葉、または話した日より後の出来事の日付）を、会話に渡す前に分ける：

| 分類 | 条件 | 会話への扱い |
| --- | --- | --- |
| AIへの質問・依頼 | 本人の発言が質問・依頼だけ、または質問・依頼があり要約の予定の文が依頼・整理のこと | 渡さない |
| 振り返り | 過去の出来事を後から話した記録、または要約の予定の文が以前の考え・振り返りのこと | 渡さない |
| 予定 | 本人の発言が予定を言っている、または出来事の日付が後 | 「予定」 |
| 希望 | 本人の発言が〜たいで、予定とは言っていない | 「希望（予定ではない）」 |
| 要約上の意図 | 予定と書いているのは AI の要約だけ | 「AIの要約上の意図（本人が予定と言った記録は無い）」 |

人物シート（P0）は従来どおりすべてを予定として表示する。Capture は変えていない。

### 4. 名前の無い記録

候補にするのは、次の両方を満たすときだけ：
- この人について何かを言う共通の言葉（ほかの2人以上の人物の記録にも出る言葉ではない）。
- 構造のつながり：同じ話題、Connect のつながり、または同じ会話（その会話にほかの人物の話が無いとき）。

どちらか一方だけでは候補にしない。候補はこれまでどおり「候補・名前の無い記録」として渡し、事実にはしない。

### 診断ページ

人物シートの診断ページに「背景に入れた理由・入れなかった理由」を追加した（会話には送らない）：
- 考え・結論：種類・重み・入れたか・理由・結びついた後からの説明。
- 予定：分類と理由。
- 名前の無い記録：根拠（同じ会話・同じ話題・Connect・共通の言葉）と、候補にした／しなかった理由。

## テスト（架空データ、`npm run test:person-context`）

1. 短い状況説明と重要な結論が混在：願い2件と結論が残り、状況説明と短い気持ちは入らない。
2. 古い重要な考えと新しい発言が多数：3月の決定が10月の8件に押し出されない。
3. 後から説明された理由：結論の下に残り、単独では二重に出ない。多数の発言と競合しても落ちない。話題が無ければ推測と表示。ほかの人物にも使う言葉だけでは結びつかない。
4. 訂正ではない新しい考え：古い結論に結びつかず、古い結論も残る。
5. AIへの質問が予定として保存：会話の予定に入らない（シートには残る）。振り返りも入らない。希望は「希望」として渡す。
6. 名前が無く同じ話題・同じ会話の無関係な記録：候補にならない。診断に根拠と理由が出る。
7. 同名・別名・別人物：確定した別名だけ結合。ほかの人物の文、似た名前は入らない。

- Retrievalだけで答えられる質問：Retrieval が渡す記録を繰り返さない。背景は小さいまま。人物が出ないときは何も足さない。
- route：新しい欄は決まった値だけ通す。古い形の payload は従来どおり表示する。

## 既知の限界・未検証

- 文の形で判断するため、句読点の無い話し言葉や、言い切りでも重要な文（「もう半年だ」に重い意味がある場合）を状況の説明と判断することがある。
- 共通の言葉は漢字・カタカナの語だけを見る。ひらがなだけの言い換えは結びつかない。
- 同じ名前の別人は区別できない（P1-B と同じ）。
- 実機のデータでの効果、実際の AI の応答の変化：未検証。
